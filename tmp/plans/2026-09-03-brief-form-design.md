# Форма брифа и шаг трёх направлений

Дата: 2026-09-03. Статус: согласовано, готово к плану реализации.

Первый вертикальный срез проекта: человек описывает бренд, получает три
визуальных направления. Картинок на этом шаге нет — они дороже всего
остального вместе взятого и заказываются только после выбора направления.

## Решения и почему

**Разбитые поля, а не одно свободное.** Модель получает размеченный вход и не
достраивает недостающее сама. Цена — форма выглядит анкетой, поэтому
обязательное поле только одно.

**Характер и эстетика — чипы плюс «своё».** Свободный текст на брифе вроде
«современно и стильно» даёт три почти одинаковых направления. Чипы связаны с
каталогом `styles.csv` в коде, а не в голове модели.

**Обязательно только «что за бренд».** Рядом индикатор полноты, который
подсказывает, чего не хватает, но не запрещает отправку. Аудитория проекта —
рекрутеры: они нажмут кнопку через пятнадцать секунд или уйдут.

**Витрина ведёт на готовый результат, а не заполняет форму.** Клик по готовому
бренду открывает сохранённый брендборд. Ноль рублей, всегда выглядит хорошо, и
те же файлы служат фикстурами для тестов и для `/break`.

Термин «витрина» — про готовые брендборды в демо. Не путать с «примерами
применения» внутри брендборда (пост в соцсети, первый экран сайта): это разные
вещи, и раньше они назывались одинаково.

Витрина показывает целый брендборд, а его вёрстки в этом срезе ещё нет. Поэтому
маршрут витрины уезжает в следующий срез вместе с карточками брендборда, а здесь
фиксируется только формат фикстуры и тест, что она проходит схему. Ссылок в
никуда форма не содержит.

**После отправки форма сворачивается в строку.** Видно связь «что попросил —
что получил», перегенерация в один клик.

## Данные

`lib/brief-schema.ts` — zod-схема, единственный источник правды. Из неё же
собираются границы длины для промпта: приём из vyveska, где промпт строится из
схемы и потому не может с ней разойтись.

| Поле | Тип | Длина | Обязательное |
|---|---|---|---|
| `brand` | строка | 10–600 | да |
| `audience` | строка | 0–300 | нет |
| `character` | чипы + строка | 0–200 | нет |
| `aesthetic` | чипы + строка | 0–200 | нет |
| `avoid` | строка | 0–300 | нет |

Пустые поля в запрос не попадают. Модель не должна видеть `"audience": ""` и
делать из этого выводы.

`lib/vocab.ts` — два списка по 8–10 бытовых слов (тёплый, дерзкий, строгий,
ремесленный, техничный, игривый и подобные). Каждое сопоставлено с несколькими
строками `styles.csv`. В промпт уезжают строки каталога, а не слово «дерзкий».

## Компоненты

```
app/page.tsx                      серверная оболочка, нейтральная
components/brief/BriefForm.tsx    "use client", всё состояние формы
components/brief/ChipGroup.tsx    мультивыбор чипов + поле «своё»
components/brief/BriefSummary.tsx свёрнутая строка после отправки
components/brief/useDirections.ts fetch и чтение стрима
app/api/directions/route.ts       единственная точка наружу
lib/brief-schema.ts               zod
lib/vocab.ts                      чипы → строки styles.csv
lib/stream.ts                     перенос из vyveska вместе с тестами
lib/fixtures/*.ts                 готовые брендборды для витрины
```

Маршрут витрины (`app/example/[slug]`) появится в следующем срезе — ему нужна
вёрстка брендборда.

Границы: `BriefForm` не знает про сеть, `useDirections` не знает про поля
брифа, `route.ts` не знает про React.

## Поток

1. Форма собирает объект и отправляет `POST /api/directions`.
2. Handler выкидывает пустые поля, валидирует схемой, проверяет суточный лимит.
3. Запрос к Polza, `stream: true`, `signal: req.signal` — уход со страницы рвёт
   запрос и не даёт жечь токены впустую.
4. `parseSSEBuffer` разбирает протокол, `parseSectionBuffer` — построчный JSON.
   Обе функции переносятся из vyveska как есть.
5. Разобранные направления уходят клиенту построчно, по мере готовности.
6. `useDirections` накапливает их, форма схлопывается в `BriefSummary`, ниже
   проявляются три карточки.

Обязательно дочитывание хвостов обоих буферов после закрытия потока. Апстрим не
завершает ответ переводом строки, и без этого последняя секция теряется всегда —
проверено на vyveska.

## Ошибки

Три состояния с разными текстами: сеть не ответила, модель вернула не то, лимит
исчерпан. Отдельно логируется `finish_reason`: без него обрыв генерации
неотличим от несошедшейся схемы.

## Лимит

Счётчик в Vercel KV, ключ — sha256 от IP с солью `APP_SALT`, TTL сутки, потолок
2 генерации. Хеширование берётся из `lib/rate-limit.ts` vyveska, сырой IP нигде
не сохраняется.

Хранилище недоступно — лимит не срабатывает, генерация идёт. Доступность важнее
экономии на одном проходе.

Полноценная БД не заводится: единственное, что надо хранить, — счётчик.

## Тесты

vitest, только чистые функции. TDD на всю демку не нужен, но разбор ответа
модели без тестов разъедется на первой же смене схемы.

- `brief-schema` — границы полей, выкидывание пустых
- `vocab` — каждый чип сопоставлен существующей строке `styles.csv`
- `stream` — переносится из vyveska с тестами
- накопление направлений — из трёх кусков собирается три карточки
- фикстуры витрины проходят схему

## Вне этого среза

Выбор направления и генерация брендборда, moodboard, PNG-экспорт, вёрстка
примеров применения, маршрут витрины. Это следующий срез.

## Открытое

Цены Polza взяты из `CLAUDE.md` и не сверены с живым каталогом. Расчёт
экономики (~37 ₽ за полный проход) держится на них — сверить до деплоя.

Модель для разбора брифа: в `CLAUDE.md` записан `claude-opus-5`, в vyveska
работает `claude-sonnet-5` вшестеро дешевле на выходе. На фоне стоимости кадров
разница невелика, но выбор надо сделать осознанно при написании промпта.
